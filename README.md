# 原神角色养成系统

一个纯前端的原神角色养成决策工具，帮你回答四个问题：

> **这个角色该配什么圣遗物？主副词条怎么选？该带什么武器、天赋先点哪个？我现有的圣遗物能配出什么效果？**

单文件网页，双击即用，**完全离线**，数据存在浏览器本地，不上传任何服务器。

---

## 为什么做这个

原神的养成信息高度分散：圣遗物该刷哪套看一个攻略、副词条优先级看另一个、天赋加点又得翻视频。更麻烦的是——**同一个角色在不同配队里定位不同，配装也完全不同**（比如行秋在蒸发队堆双暴输出，在雷神队可能得先保充能）。

这个项目想把这些信息结构化，并且用「配队方案」作为组织单位，让配装推荐随配队自然变化。

---

## 功能

| 模块 | 说明 |
|------|------|
| **角色库** | 按元素/星级筛选、搜索；详情页按「配队方案」分标签展示完整养成攻略 |
| **我的背包** | 录入自己拥有的圣遗物，副词条手动填数值，支持编辑/删除/锁定/筛选 |
| **配装推荐** | 选角色 + 配队方案，从背包中自动匹配最优组合，输出 **Top3** 方案与综合评分 |
| **刷取规划** | 对比目标配装与现有背包，列出缺口（缺套装/缺主词条）并给出推荐副本 |
| **数据管理** | 背包数据导入/导出 JSON，方便备份与换设备迁移 |

每个角色的养成攻略包含：

- **配队方案**：阵容构成、角色定位、配队思路
- **圣遗物**：推荐套装（4件套/2+2）、完整套装效果、掉落副本、主词条、副词条优先级
- **武器**：主推 + 备选，附选择理由
- **天赋**：加点优先级（A/E/Q 顺序）+ 目标等级

## 核心设计：配装挂在「配队」下，而不是角色下

这是整个项目最关键的一个数据建模决策：

```
角色 Character
  └─ 配队方案 teamBuilds[]        ← 一个角色可有多个主流配队
       ├─ 配队名 + 阵容 + 定位
       ├─ 配队思路
       ├─ 圣遗物（套装 + 主词条 + 副词条优先级）
       ├─ 武器（主推 + 备选）
       └─ 天赋（优先级 + 目标等级）
```

如果按常规做法把配装直接挂在角色上，就只能给一个角色一套配装，遇到「行秋在不同队里配装不同」这种情况就只能靠备注硬塞、或者干脆写死一套。挂到配队方案下之后，**配装差异由数据模型天然承载**，不需要任何特殊处理。

## 快速开始

不需要安装、不需要构建、不需要联网。

```bash
git clone https://github.com/你的用户名/你的仓库名.git
cd 你的仓库名
```

然后**双击 `index.html`** 用浏览器打开即可。

或者直接开 GitHub Pages 在线访问（见下方「部署」）。

### 第一次使用建议顺序

1. 打开「**角色库**」，找到你想练的角色，看看有哪些配队方案、各自配什么
2. 切到「**我的背包**」，把你现有的圣遗物录进去（副词条填数值，如 `10.5%`）
3. 去「**配装推荐**」，选这个角色和配队，看系统从你背包里配出了什么
4. 去「**刷取规划**」，看还缺什么、该去刷哪个副本

## 项目结构

```
.
├── index.html      # 主程序：页面结构 + 样式 + 交互逻辑（约 1170 行）
├── data.js         # 数据层：角色 / 圣遗物套装 / 武器 / 词条池
├── 设计方案.md      # 完整设计文档（数据模型、算法、路线图）
├── .gitignore
└── README.md
```

**为什么拆成两个文件**：数据是长期维护、会被反复补充的部分，逻辑则相对稳定。拆开后补数据只需要动 `data.js`，不用在几千行 HTML 里翻找，也方便以后用脚本批量生成数据。

| 项 | 数量 |

| 武器 | 30 把 |
| 配队方案 | 28 个（部分角色有 2 套） |

## 配装推荐算法

### 单件评分

```
单件得分 = 主词条匹配分(命中推荐主词条 = 100 分)
         + Σ(副词条权重 × 词条数值)
         + 等级 × 0.2
```

副词条权重来自该配队方案下的优先级列表：第 1 优先级 5 分，第 2 优先级 4 分，依此类推。所以「暴击率 10.5%」和「防御力 10.5%」在同一件装备上得分完全不同。

### 组合搜索

1. 按配队方案要求的套装筛选背包中可用的圣遗物
2. 五个部位（花/羽/沙/杯/冠）各取一件，不能重复
3. 按总分从高到低排序，贪心输出 Top3 方案
4. 部位凑不齐时标记「缺口」，交由刷取规划模块处理

背包件数通常不超过百件，贪心搜索即可，不需要全排列。

## 技术栈

- **原生 HTML + CSS + JavaScript（ES6+）**
- **无任何框架、无任何 CDN 依赖**——这是刻意的选择，保证断网可用、单文件可传、十年后打开还能跑
- **localStorage** 做数据持久化
- 支持昼夜主题切换、响应式布局、打印样式

## 已知限制

- **数据尚未覆盖全部角色**：目前 22 个角色，扩充中
- **配装推荐依赖背包录入质量**：需要手动录入，未接入任何游戏账号读取
- **数据基于公开攻略整理**，会随游戏版本变化，仅供参考，不保证与当前版本完全一致
- **纯本地存储**：清除浏览器数据会丢失背包，请定期用「设置 → 导出」备份
